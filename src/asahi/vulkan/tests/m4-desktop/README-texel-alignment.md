# Gen9 single-texel buffer alignment (J713, 2026-09-16)

Both `uniformTexelBufferOffsetSingleTexelAlignment` and
`storageTexelBufferOffsetSingleTexelAlignment` are now true on Gen9. This
closes the vkd3d-proton baseline property gap identified by the Steam audit.
Hardware evidence is M4/G16G only; Gen10 remains gated.

Gen9's non-extended linear texture descriptor already reserves word 2 for
software buffer size/offset, at the same bit positions as AGX2. Allow the
existing shader offset crawl for those buffer views, while rejecting overlap
with hardware extensions, mip ranges, arrays, compression or tiled layouts.
Storage descriptors keep the tail in the separate software PBE; the native
heap PBE receives the aligned base with no software offset. Image loads,
stores and atomics therefore apply the offset exactly once.

RGB32 uniform views may start at a four-byte component offset, including
offsets not divisible by the 12-byte texel size. Their Gen9 software tail is
in bytes and the raw-load lowering adds it to the original view coordinate.
Other formats retain texel units. Logical buffer-size queries and bounds
checks continue to use the unshifted view range.

Descriptors include the leading tail in their physical row count, so the last
texel of a 16,384-element view can land in row 2. Reserve 15 elements in Gen9's
maximum advertised texel-buffer size (268,435,441 instead of 268,435,456) so
the largest legal view plus a one-byte-format tail still fits the hardware's
16,384 by 16,384 limit. This bounds the capability for all permitted offsets;
it does not skip test formats or change CTS coverage.

## Validation

All hardware runs use the mandatory 60-second watchdog, six-channel thermal
monitor, unchanged 60-second per-case limit and 12 CTS workers.

- 870 minimum-alignment image cases: 490 Pass, 380 NotSupported. All skips
  name separate unsupported image/buffer format requirements. No alignment
  failures; the tests now choose the advertised smaller offsets.
- 2,400 nonzero-offset texel descriptor-binding cases: all Pass.
- Sixteen independent compute oracles: all Pass on host lavapipe and M4.
  Each checks a full 1 MiB allocation against independently generated bytes,
  including unchanged prefixes/suffixes and output guards. R8/R32 reads and
  stores cross the 16,384-texel row boundary at offsets 1/15 or 4/12 bytes;
  R32 atomics test both offsets. RGB32 uint/float use 4/8/12-byte offsets.
  All also check the logical view size. The CTS image-load/store cases skip
  RGB32 for unrelated storage-format requirements, so these oracles supply
  the missing direct coverage.
- Host descriptor test checks all 16 tail values, native/legacy software
  crawl agreement, software/hardware PBE separation and extension rejection.
- Host and ARM64 library builds pass. Rebuilt Asahi suite: 103 Pass and the
  same 11 known failures. The prior register-bank build break is fixed.
- Unchanged 1,001-case regression: 815 Pass, 186 NotSupported, no failures.

Frozen catalog indices and hash are retained in each full run's metadata;
compact outcomes are under `texel-alignment/`. Evidence:

## Reproduction tools

`tools/texel-alignment-cases.py NEW_DIRECTORY` creates the 16 shaders,
inputs, expected bytes, case manifest and bounded child runner. Compile each
`shader.comp` with `glslangValidator -V -o shader.spv`. Build the extended
`tools/vk-buffer-oracle.c` for the target with the existing sysroot and `-ldl`.
The oracle uses `M4_ORACLE_BINDING_COUNT=2` with the texel view in the first
half and a disjoint SSBO in the second. `M4_ORACLE_TEXEL_FORMAT`,
`M4_ORACLE_TEXEL_OFFSET`, `M4_ORACLE_TEXEL_RANGE` and
`M4_ORACLE_TEXEL_STORAGE=1` select the view. It requires the advertised
alignment properties. Existing raw-buffer modes retain their behavior.

Run generated `run.py OUTPUT ORACLE_BINARY` only through `gpu-experiment.py`;
the tested command uses `/root/run-m4-gl.py` to set the private driver
environment. The generator never executes GPU work. The root oracle retains
pre-existing optional 16-bit diagnostic modes; the tracked copy only adds
the two-binding and texel-view support needed here. Both copies passed the
software oracle. Exact hardware inputs and executable hashes are recorded.

These are driver capability tests, not a full DirectX game validation.
